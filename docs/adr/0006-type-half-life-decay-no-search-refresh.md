# 0006. 유형별 반감기 감쇠와 검색 비갱신

- 상태: 채택
- 날짜: 2026-07-07

## 맥락
오래 재확인되지 않은 기억은 신뢰도가 떨어져야 합니다. 사실 유형마다 유효 기간이 다릅니다. 검색 접근으로 감쇠를 리셋하면 자주 검색되는 사실이 영원히 살아남습니다.

## 결정
- 유효 신뢰도 = `confidence × exp(-ln2 × last_confirmed_at 이후 경과일 / 반감기)`.
- 기본 반감기(일): preference 180, constraint 180, decision 90, event 30, entity 365. `memstore.half-life-days` 설정값입니다.
- 유효 신뢰도가 0.15 미만이면 expired로 전환합니다(삭제 아님, 0002).
- 유지보수 잡(`MaintenanceJob`)은 매일 03:00 스케줄과 `POST /internal/maintenance/run` 수동 트리거로 실행됩니다.
- 검색은 `last_confirmed_at`을 갱신하지 않습니다. 재추출 확인과 정정만 갱신합니다.

## 대안
- 검색할 때마다 갱신: 자주 검색되는 사실이 감쇠하지 않는 반향실이 생깁니다.
- 물리 삭제로 망각: 0002의 소프트 상태 원칙과 맞지 않습니다.

## 결과
- 장점: expired 사실도 `include_inactive=true`로 조회할 수 있어 망각을 되짚을 수 있습니다.
- 장점: 같은 반감기 설정을 검색 최근성 점수(0004)와 공유합니다.
- 단점/감수한 점: 계속 쓰이지만 재진술되지 않는 사실도 감쇠해 만료될 수 있습니다.
