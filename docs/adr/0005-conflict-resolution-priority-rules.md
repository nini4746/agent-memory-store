# 0005. 모순 기억 충돌 해소 우선순위 규칙

- 상태: 채택
- 날짜: 2026-07-07

## 맥락
새 세션에서 기존 사실과 모순되는 진술이 나오면 검색이 둘 다 돌려주면 안 됩니다. 어느 쪽이 이기는지 결정적인 규칙이 필요하고, 판단할 근거가 없는 경우의 처리도 정해야 합니다.

## 결정
- 감지: 추출 시 정규화 유사도 0.80 이상 상위 5개 활성 사실과 LLM 쌍 분류(duplicate | contradicts | refines | unrelated)를 합니다.
- duplicate는 기존 사실을 확인 처리하고, refines는 신규 저장 + refines 관계로 둘 다 active입니다.
- contradicts 우선순위: 명시적 정정 > 최신 세션 > 최신 발화 (`DefaultConflictResolver`).
  - 명시적 정정: 대상은 retracted, 정정 사실은 confidence 0.95, 전파(0007)를 트리거합니다.
  - 최신 세션/발화: 패자는 superseded + `superseded_by` 설정.
- 같은 발화 안의 모순은 둘 다 저장하고 둘 다 needs_review로 둡니다.
- retracted 사실과 같은 진술이 다시 나오면 자동 부활하지 않고 needs_review로 저장합니다.
- 2026-07-12: 후보 창(5, 0.80)을 `memstore.conflict.candidate-limit` / `candidate-threshold` 설정값으로 바꾸고, 창이 포화되면 경고 로그를 남깁니다.

## 대안
- 같은 발화 내 모순에서 한쪽 자동 선택: 우선순위 규칙으로 승자를 정할 근거가 없습니다.
- retracted 진술 자동 부활: 사용자가 철회한 기억이 조용히 되살아납니다.
- 후보 창 고정값: 창 밖 모순을 놓칠 수 있다는 한계가 숨고, 넓힐 수도 없습니다.

## 결과
- 장점: "3월 A, 6월 B" 시나리오에서 검색은 B만 반환하고, A는 inspect로 이력이 남습니다.
- 장점: 판단 불가 경우는 needs_review로 안전하게 남겨 0007의 재검토 대상이 됩니다.
- 단점/감수한 점: 후보 창 밖의 모순은 여전히 놓칠 수 있습니다. 포화 경고로 드러낼 뿐입니다.
- 단점/감수한 점: 임계값은 정규화 스케일에 적용됩니다. 원시 코사인 기준으로는 0.60에 해당해, 실 임베딩 모델 튜닝 시 이 차이를 인지해야 합니다.
