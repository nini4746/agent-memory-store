# 0004. 가중 점수 랭킹과 토큰 예산 그리디 패킹

- 상태: 채택
- 날짜: 2026-07-07

## 맥락
에이전트 컨텍스트에 넣을 기억은 관련성뿐 아니라 최근성과 신뢰도도 반영해야 합니다. 응답은 지정한 토큰 예산을 절대 넘으면 안 됩니다(N3).

## 결정
- 점수: `score = 0.55×sim + 0.25×rec + 0.20×conf`. 가중치는 `memstore.scoring` 설정값입니다.
  - sim은 코사인 유사도를 `(1 + cos) / 2`로 [0,1] 정규화합니다.
  - rec는 유형별 반감기(0006과 공유)로 계산합니다.
  - needs_review 사실은 conf에 0.5배 페널티를 줍니다.
- 벡터 검색으로 상위 50개(`VECTOR_TOP_K`)를 가져온 뒤 점수를 매깁니다. 기본 필터는 `status = active`입니다.
- 예산: `budget_tokens` 기본 2000, 상한 8000.
- 토큰 추정: `ceil(문자수/4 × 1.1)` (`TokenEstimator`).
- 패킹: 점수 내림차순 그리디. 안 들어가는 사실은 건너뛰고 다음 사실을 시도합니다. 아무것도 못 넣으면 빈 결과와 경고를 반환합니다(`BudgetPacker`).

## 대안
- 실제 토크나이저: 의존성이 늘어납니다. 보수적으로 크게 잡는 추정으로 예산 초과를 막습니다.
- 첫 실패에서 중단: 큰 사실 하나 때문에 뒤의 작은 사실들이 빠집니다.
- 최적 배낭: SDS에 대안으로 기록되어 있으나 택하지 않은 구체적 사유는 남아 있지 않습니다.

## 결과
- 장점: property 테스트 100케이스에서 추정 토큰 합이 예산을 넘지 않습니다.
- 단점/감수한 점: 추정이 크게 잡혀 실제 예산을 덜 채울 수 있습니다.
- 단점/감수한 점: type 필터가 상위 50개 이후에 적용되어, 그 밖의 해당 type 사실은 누락될 수 있습니다(recall 한계).
