# Plan 10: 벤치마크 스위트와 하니스

## 목표
SPEC R8(벤치마크)을 구현한다 - MemFail 원본 조사, 자체 시나리오 스위트 30개 이상, 하니스와 bench-report.md 생성, 전체 80% 달성.

## 컨텍스트
- 선행: Plan 09 (하니스는 MCP 툴 경유로 시드/질의)
- 명세: .planning/SPEC.md R8. 핵심 규칙:
  - 먼저 MemFail(arXiv:2605.26667)의 데이터셋/코드 공개 여부 조사. 사용 가능하면 통합, 불가면 사유를 기록하고 자체 스위트로 진행
  - 자체 스위트: YAML 시나리오 30개 이상 - 모순 갱신 10, 명시적 정정 8, 감쇠/노후 6, 출처 추적 3, 예산/라우팅 3
  - 시나리오 형식: 시드 세션들(발화 배열, 상대 시각 오프셋 포함) + 트리거(extract/maintenance 실행) + 질의 + 기대 결과
  - 판정: 기대 fact 키워드/id 포함 여부의 결정적 판정 우선. 자유 텍스트 응답만 LLM 저지(루브릭 고정, temperature 0)
  - 감쇠 시나리오는 시계 조작 필요 - 하니스가 last_confirmed_at을 직접 세팅하는 테스트 훅 사용
  - 실행에는 실제 LLM/임베딩 키 필요 - CI 필수 아님, 로컬 실행 후 리포트 커밋
- 목표치: 전체 ≥ 80%, 모순 갱신 카테고리 ≥ 80%. 미달 시 이 plan 안에서 프롬프트/정책 튜닝 반복

## 작업
1. MemFail 원본 조사 - arXiv 페이지/저자 레포 확인, 결과를 `bench/MEMFAIL-NOTES.md`에 기록
2. 시나리오 스키마 정의 + `bench/scenarios/*.yaml` 30개 이상 작성 (카테고리 구성 준수)
3. 하니스 - Java 실행기(별도 gradle task `benchRun`): DB 초기화 → 시나리오별 MCP 툴 호출 시드 → 트리거 → 질의 → 판정 → 집계
4. LLM 저지 - 자유 텍스트 판정용, 기대 근거와 함께 pass/fail만 출력
5. `bench-report.md` 생성 - 카테고리별 M/N 표, 실패 시나리오 목록, 사용 모델/임베딩 기록
6. 실행 및 미달 시 튜닝 반복 (추출/충돌 프롬프트, 유사도 임계, 가중치)

## must-haves
- 시나리오가 코드가 아닌 데이터(YAML) - 스위트 확장이 코드 수정 없이 가능
- 리포트에 실행 환경(모델 id, 임베딩 모델, 실행 일시) 기록 - 재현성
